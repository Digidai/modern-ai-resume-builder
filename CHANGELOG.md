# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

- HTTPS responses send `Strict-Transport-Security: max-age=31536000`, so after one visit browsers go straight to HTTPS instead of first asking over plain HTTP and being redirected. Subdomains are not included.
- Typing stays quick in long resumes: the editor preview used to re-measure every page on each keystroke, which on a 9-page CV made a keystroke take over 200 ms on a mid-range phone. It now measures once you pause (a quarter of a second), so keystrokes take under 50 ms there; the page count, page guides and page-count suggestions follow just after, and Download PDF waits for the measurement so the PDF always gets the final page count. The PDF render page still measures right away.
- On phones, the four links in the site menu fit on screens 360 px and wider instead of scrolling sideways with FAQ cut off at the edge, and on narrow phones the template cards' tags wrap onto a second line instead of pushing the Templates page wider than the screen.
- On phones, the editor shows which resume you are editing ("Senior Product Designer (copy) · 2 of 2") in a thin line under the header once there are two or more, since the resume menu button there has room only for its icon. Tapping the line opens the resume menu.
- On phones, the whole editor page could scroll about 370 px in the Profile tab, taking the header off screen (it happened after duplicating a resume, for example): the photo field's hidden file input was positioned against the page instead of the editor panel. The panel now contains it.
- Small polish: the number of job titles reads "1,204" instead of "1204" on the home, directory and 404 pages, in their search descriptions, the directory's share image and llms.txt; the editor's "1 suggestion" label no longer wraps onto two lines on phones; and Import resume in More actions has its own sparkles icon instead of sharing Open in Overleaf's code icon.
- Import resume and the BibTeX/ORCID import each keep their step in one state (input, reading, converting or fetching, review), shown on the dialog and panel as `data-state` so tests and agents can wait for a step. Fixes found along the way: the dialog stays locked while a file's photo is prepared instead of unlocking briefly before converting; switching to Import BibTeX during an ORCID fetch no longer shows that fetch's works there; and Copy buttons keep "Copied" for the full 2 seconds after a second click, and say "Couldn't copy" when the browser refuses.
- Pages paint about half a second sooner on a slow connection: each prerendered page carries the CSS its own markup uses inline (about 6–9 KB compressed, plus the Inter @font-face rules), and the full stylesheet with all 89 templates' styles loads from the end of the page instead of blocking the first paint. The build does this with Beasties; the PDF render page is left as it was.
- Download Word (.docx) in More actions: an editable single-column Word file for portals and recruiters that ask for one, in the layout ATS parsers read best (Heading 1 sections, Word bullet lists, dates on a right tab stop, live links, A4 or US Letter as chosen). It is built in the browser with no extra library, and Import resume reads it back.
- Resume checks in the editor: a line above every tab lists suggestions as you type, worked out in the browser without AI: missing name, contact details or summary, the sample email, positions without dates, ending before they start, without a single number (the most recent one, or an older one with three or more bullets) or with bullets over two lines (Chinese, Japanese and Korean text counts double width), fewer than three skills, and more pages than the template aims for. Selecting one opens the tab and the entry that fixes it.
- The template picker in the editor is one Tab stop instead of 89: arrow keys move between templates and switch to them, Home and End jump to the first and last, and Tab moves on to the next control.
- Several resumes in one browser, for example one per job you apply to. The resume menu in the editor header lists them, switches between them, starts a new blank one (keeping the template and style) or a copy of the current one, and renames or deletes them (Undo brings a deleted one back). They are stored only in this browser, like the single resume before.
- Save backup with more than one resume saves all of them in one file, and Import backup adds them all to the resume menu (in a fresh browser the first one replaces the sample). A backup of one resume still replaces the current one, with Undo. An agent's #resume= link opens as a new resume when yours has changes, instead of replacing it.
- Start from example on a job page opens the example as a new resume and keeps yours in the resume menu (an untouched sample or empty resume is replaced instead).
- The same letter-spacing limit (0.08em) now applies to the design templates too, so their headings, titles and company names also extract as words for ATS parsers (69 spots in 36 templates; the look barely changes). The test covers every template.
- PDFs read correctly by ATS parsers in every ATS-friendly template. Section headings with wide letter-spacing came out of the PDF as "E D U C AT I O N" in 16 of the 36 (Compact, Executive, Graduate, Keystone, Lateral, Opal, Plain, Silk, Vital, Atlas, Bedrock, Harbor, Linear, Slate, Meridian, Academic), so a parser missed them: letter-spacing is now at most 0.08em in those templates and the shared single-column layout (a test keeps it there), Meridian's headings and Academic's name are capitals instead of synthesised small caps, and Latin Modern (Linear) has TrueType outlines, which Chrome embeds as a normal font instead of Type 3.
- Import resume: start from an existing PDF, Word (.docx), LaTeX or plain-text resume. The browser reads the file's text (the file isn't uploaded), AI fills in every section, and you check the result as pages before it replaces your resume (Undo restores the old one). Opens from More actions, from "Import a PDF or Word file" on the home page, or at /editor/?import. Replaces Import LaTeX, which it includes.
- Import resume also brings in the photo from a PDF or Word file (the largest portrait-shaped picture near the top of the first page); it stays in the browser. The preview shows it in Essential when the current template has no photo, and a checkbox leaves it out.
- Retired eight templates that were near-copies of another one, keeping the layouts that differ: Quill (now Folio), Tribune (Harbor), Beacon (Cobalt), Keel (Bedrock), Crest and Zenith (Nova), Pearl (Aurora) and Haven (Cameo). Resumes, share links, agent calls and /templates/ pages that use an old id open the replacement. 89 templates.

- Paper size: A4 or US Letter, under Template → Style. The preview, page count, Fit to one page, PDF (server and browser), LaTeX export and the agent API (`paper`) all follow it; example resumes have their own Letter text sizes so they still fit one page.
- Three more ATS-friendly templates modelled on the most used LaTeX resumes: Oxford (moderncv classic: grey italic title, accent bars and a left date column; shows the academic sections), Standard (Gayle McDowell's CareerCup format: Times, small caps, firm · role · dates) and Lumen (billryan/resume: centred header, icon-led section titles). 52 templates.

- Publications: a new editor section (title, authors, venue, year, DOI) for academic and research CVs, shown by Scholar, Academic, Plain, Text and Graduate, with your name bolded in the author list. Accepted by the schema, MCP and API, and imported from JSON Resume.
- Grants and awards (title, funder, year, amount or role) and Talks (title, event, location, year): two more academic CV sections, shown by the same templates as Publications. Scholar puts their years in its gutter. Accepted by the schema, MCP and API; JSON Resume `awards` are imported.
- Import LaTeX (.tex): paste or upload a LaTeX resume or CV (moderncv, Awesome-CV, Jake's Resume and others); AI converts it, including publications, grants, talks and teaching, and you check it as pages before it replaces the resume (Undo restores the old one).
- Agents: two new MCP tools and HTTP endpoints. `import_publications` (`POST /api/agent/publications`) reads an ORCID record or BibTeX with type and year filters; `export_latex` (`POST /api/agent/latex`) returns the resume as a .tex file for Overleaf. The skill, OpenAPI spec and /agents page document them, along with how agents convert an existing LaTeX CV.
