# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

- PDFs in Latin Modern (the Linear template, or any template with the Latin Modern font) contain plain letters where the font draws ligatures, so "Certified", "office", "fluent" and "affiliate" come out of the PDF as those words instead of "Certiﬁed", "oﬃce", "ﬂuent" and "aﬃliate" with single ligature characters, which an applicant tracking system's keyword search doesn't match. The page looks the same. The other nine fonts were already fine.
- PDFs from eight templates with timeline dots (Timeline and Opal, both marked ATS, plus Creative, Ginto, Linen, Path, Sidebar and Wave) list your experience in reading order. Their PDFs stored every experience entry after the rest of the page (and Path its whole timeline column after the sidebar), so applicant tracking systems and AI screeners that read the PDF's text in order, and Import resume itself, saw the Experience heading followed by Projects, Education and Skills, with the jobs at the very end. The pages look exactly the same.
- Paper size (A4 / US Letter) works like the accent colours from the keyboard: it is one Tab stop on the selected size, and the arrow keys switch between the two. Before, each size was a separate Tab stop and the arrow keys did nothing, unlike every other choice in the editor.
- AI writing help and Download PDF keep working when the site is open in more than one tab. Every page you opened issued the browser a new AI client id, so a tab opened earlier (the editor, say, after you looked at a template in a new tab) failed with "AI verification expired. Refresh the page and try again." until it was reloaded; two editor tabs also kept replacing each other's AI session. Pages now reuse the browser's id and session.
- Printing the resume from the editor with the browser's Print (Cmd/Ctrl+P) has its page margins again. Since the stylesheet started loading after the first paint, its page default of no margins overrode the resume's 15 mm, so templates without their own background printed with text running to the edge of the paper. Download PDF, full-bleed templates and Agent API PDFs were not affected.
- Pasting a bulleted list from Google Docs, a web page or LinkedIn into "What you did" or a project's Description keeps the bullets: each item becomes a "- " line, and the resume shows them as bullet points. Before, every browser dropped the markers, so the items became plain paragraphs (indented by spaces in Firefox). A list pasted after existing text starts on its own line, and one Undo removes the whole paste. Pasting text without a list works as before.
- When the browser's storage is full, importing a backup (or starting over, or loading a resume from a link or Import resume) says so instead of "Backup imported." next to a "not saved" banner: "Backup imported, but not saved: this browser's storage is full…", still with Undo. Importing a backup of several resumes into a fresh browser with full storage now reports the full storage instead of "That file is not a ModernCV backup".
- On the smallest phones (under 360 px wide, such as an iPhone SE in zoomed display mode), the site menu's first link reads "Examples" instead of "Resume examples", so all four links fit on one row down to 320 px instead of FAQ being cut off at the edge.
- The resume menu works from the keyboard without losing your place. Opening it moves focus to the resume you're editing, Esc returns focus to the button that opened it (the resume name line on phones), finishing a rename returns to that resume's Rename button, deleting a resume moves focus to the next one, and tabbing out of the menu closes it. Before, renaming or deleting dropped focus to the top of the page, and the menu stayed open after focus had left it.
- Dates typed in Firefox and Safari come out the same as in Chrome. Those browsers have no month picker, so the Start and End fields were plain text and "2020/3" or "03/2021" went onto the resume as typed, next to Chrome-entered dates shown as "Mar 2020", and the "ends before it starts" check skipped them. On leaving the field, "Jan 2020", "September 2021", "2020/3", "03/2021" and "2020年3月" now become the same month Chrome's picker gives; a year on its own or text such as "Summer 2020" stays as typed.
- Notifications wait while the pointer is over them or keyboard focus is inside them, then count down again from where they stopped, so there is time to read one and reach its Undo (before, "Removed …" disappeared after 7 seconds even with focus on Undo). Error messages now stay 7 seconds instead of 4.
- Keyboard focus stays in place when you reorder or remove entries in the editor. Moving a position, school, project or other entry up or down keeps focus on its move buttons (the other one when it reaches the top or bottom), removing an entry moves focus to the next entry (or "Add" once the list is empty), and removing a skill moves it to the next skill. Before, focus fell back to the top of the page each time.
- The editor keeps working when the connection drops. Before, choosing a template (or anything else that loads on demand, such as a resume font) while offline reloaded the page to "pick up a new deploy", which swapped the editor for the browser's offline page. Now the page stays: a template that can't load shows a note inside its own paper, Download PDF says you're offline, and once the connection is back the note asks for a reload instead of the page reloading under you (browsers keep failing an import that failed offline until the page reloads).
- Edits made just before closing the tab are kept. The resume is saved a third of a second after you stop typing, so closing the tab within that moment lost the last edit; it is now also saved as the page is closed or reloaded.
- The agent API answers a known route called with the wrong method with `405 Method Not Allowed` and an `Allow` header, instead of `404 Unknown agent API route`: a `POST /api/agent/templates` (or `/guide`, `/example`) used to look like the route didn't exist. Those three routes now also answer `HEAD`, and the site's own `/api/ai`, `/api/pdf`, `/api/ai/session` and `/api/orcid` send `Allow` with their 405s too.
- On template pages, the large preview is a picture of the template: the sample resume's email and profile links can no longer be clicked or reached with Tab, and screen readers announce it as "Halo template with a sample resume" instead of reading out the sample text. Lighthouse accessibility on these pages goes from 96 to 100 (the tiny sample links failed the touch-target check).
- The editor's More actions menu works from the keyboard like a menu: opening it moves focus to the first item, ↑/↓/Home/End move between items, Tab closes it, and Esc or choosing an item returns focus to the ⋯ button. Before, focus stayed on the button, so screen readers announced a menu that keyboard users had to Tab into item by item.
- Pages no longer jump when the Inter font arrives on a slow connection. Until it loads, the site's text uses Arial (Roboto on Android) scaled to Inter's width and line height, so headings wrap the same way; on the role pages the example resume used to drop about 40 px, a layout shift of 0.23 (Google counts over 0.1 as poor), and now measures 0.
- HTTPS responses send `Strict-Transport-Security: max-age=31536000`, so after one visit browsers go straight to HTTPS instead of first asking over plain HTTP and being redirected. Subdomains are not included.
- Typing stays quick in long resumes: the editor preview used to re-measure every page on each keystroke, which on a 9-page CV made a keystroke take over 200 ms on a mid-range phone. It now measures once you pause (a quarter of a second), so keystrokes take under 50 ms there; the page count, page guides and page-count suggestions follow just after, and Download PDF waits for the measurement so the PDF always gets the final page count. The PDF render page still measures right away.
- On phones, the four links in the site menu fit on screens 360 px and wider instead of scrolling sideways with FAQ cut off at the edge, and on narrow phones the template cards' tags wrap onto a second line instead of pushing the Templates page wider than the screen.
- On phones, the editor shows which resume you are editing ("Senior Product Designer (copy) · 2 of 2") in a thin line under the header once there are two or more, since the resume menu button there has room only for its icon. Tapping the line opens the resume menu.
- On phones, the whole editor page could scroll about 370 px in the Profile tab, taking the header off screen (it happened after duplicating a resume, for example): the photo field's hidden file input was positioned against the page instead of the editor panel. The panel now contains it.
- Small polish: the number of job titles reads "1,204" instead of "1204" on the home, directory and 404 pages, in their search descriptions, the directory's share image and llms.txt; the editor's "1 suggestion" label no longer wraps onto two lines on phones; and Import resume in More actions has its own sparkles icon instead of sharing Open in Overleaf's code icon.
- Import resume and the BibTeX/ORCID import each keep their step in one state (input, reading, converting or fetching, review), shown on the dialog and panel as `data-state` so tests and agents can wait for a step. Fixes found along the way: the dialog stays locked while a file's photo is prepared instead of unlocking briefly before converting; switching to Import BibTeX during an ORCID fetch no longer shows that fetch's works there; and Copy buttons keep "Copied" for the full 2 seconds after a second click, and say "Couldn't copy" when the browser refuses.
- Pages paint about half a second sooner on a slow connection: each prerendered page carries the CSS its own markup uses inline (about 6–9 KB compressed, plus the Inter @font-face rules), and the full stylesheet with all 89 templates' styles loads from the end of the page instead of blocking the first paint. The build does this with Beasties; the PDF render page is left as it was.
- Download Word (.docx) in More actions: an editable single-column Word file for portals and recruiters that ask for one, in the layout ATS parsers read best (Heading 1 sections, Word bullet lists, dates on a right tab stop, live links, A4 or US Letter as chosen). It is built in the browser with no extra library, and Import resume reads it back.
- Resume checks in the editor: a line above every tab lists suggestions as you type, worked out in the browser without AI: missing name, contact details or summary, the sample email, positions without dates, ending before they start, without a single number (the most recent one, or an older one with three or more bullets) or with bullets over two lines (Chinese, Japanese and Korean text counts double width), fewer than three skills, and more pages than the template aims for. Selecting one opens the tab and the entry that fixes it.
- The template picker in the editor is one Tab stop instead of 89: arrow keys move between templates and switch to them, Home and End jump to the first and last, and Tab moves on to the next control.
- Several resumes in one browser, for example one per job you apply to. The resume menu in the editor header lists them, switches between them, starts a new blank one (keeping the template and style) or a copy of the current one, and renames or deletes them (Undo brings a deleted one back). They are stored only in this browser, like the single resume before.
- Save backup with more than one resume saves all of them in one file, and Import backup adds them all to the resume menu (in a fresh browser the first one replaces the sample). A backup of one resume still replaces the current one, with Undo. An agent's #resume= link opens as a new resume when yours has changes, instead of replacing it.
- Start from example on a job page opens the example as a new resume and keeps yours in the resume menu (an untouched sample or empty resume is replaced instead).
- The same letter-spacing limit (0.08em) now applies to the design templates too, so their headings, titles and company names also extract as words for ATS parsers (69 spots in 36 templates; the look barely changes). The test covers every template.
- PDFs read correctly by ATS parsers in every ATS-friendly template. Section headings with wide letter-spacing came out of the PDF as "E D U C AT I O N" in 16 of the 36 (Compact, Executive, Graduate, Keystone, Lateral, Opal, Plain, Silk, Vital, Atlas, Bedrock, Harbor, Linear, Slate, Meridian, Academic), so a parser missed them: letter-spacing is now at most 0.08em in those templates and the shared single-column layout (a test keeps it there), Meridian's headings and Academic's name are capitals instead of synthesised small caps, and Latin Modern (Linear) has TrueType outlines, which Chrome embeds as a normal font instead of Type 3.
- Import resume: start from an existing PDF, Word (.docx), LaTeX or plain-text resume. The browser reads the file's text (the file isn't uploaded), AI fills in every section, and you check the result as pages before it replaces your resume (Undo restores the old one). Opens from More actions, from "Import a PDF or Word file" on the home page, or at /editor/?import. Replaces Import LaTeX, which it includes.
- Import resume also brings in the photo from a PDF or Word file (the largest portrait-shaped picture near the top of the first page); it stays in the browser. The preview shows it in Essential when the current template has no photo, and a checkbox leaves it out.
